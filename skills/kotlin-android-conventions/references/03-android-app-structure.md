# kotlin-android-conventions §3 — Android app structure and tests

> Section 3 of `skills/kotlin-android-conventions`. Read it when a module, a layer, a ViewModel, a
> repository, a build variant or a test is added. Taken from one reference app's agent guide and architecture
> write-up; it describes how that sample works, not a mandate. The other sections and the guardrails stay in
> `SKILL.md`.

1. **Three layers, data flowing up and events flowing down:** a data layer (repositories over local and
   remote sources), an optional domain layer (use cases combining repositories), a UI layer (state holders
   exposing UI state as a stream, screens that render it). Higher layers react to changes in lower ones. The
   architecture is not a generic "clean architecture" and its concepts do not transfer one to one.
2. **Streams carry the data.** The repository exposes reactive streams; the state holder combines them into
   one UI state with an explicit loading state; the UI collects it.
3. **Offline first for synced data:** the local database is the source the UI reads, a background job
   synchronises remote data into it, and the database model stays internal to the data layer: it is mapped to
   a UI-facing model before it leaves.
4. **Modularise by layer and feature** (an app module, feature modules, core and shared modules) to support
   several developers and keep build times down.
5. **Build flavors separate the data origin:** a `demo` flavor that uses local data and a `prod` flavor that
   talks to the real service, each in `debug` and `release` build types. Name the variant when running a
   build or a test.
6. **Tests:** local tests use the coroutines test utilities, a flow-testing library for complex stream tests
   and an assertion library; UI tests use the Compose test rule with a plain component activity, and larger
   tests that start real activities live in the app module. Gradle-managed devices run instrumented tests in
   CI.
7. **Screenshot tests are generated by CI** and never committed from a workstation, so the reference images
   come from one environment.
8. **Run the project's formatter task before the lint and test tasks;** report any that were not run.

# go-performance §3 — Garbage collector

The memory limit and the container side are `go-container-runtime` §2; this section is about judging a
collector change.

## 3.1 GOGC is a trade, not a fix
The collector guide states that `GOGC` determines the trade-off between collector CPU and memory, and that
doubling it roughly doubles heap overhead and roughly halves collector CPU cost, and vice versa. It is set
by the `GOGC` environment variable or `runtime/debug.SetGCPercent`; `GOGC=off` disables collection, which
only suits a program with a bounded lifetime or an enforced memory limit (the second half is own guidance).
Change it only after §1 shows collector cost, and measure memory as well as time.

## 3.2 Toolchain upgrades change the collector
1. **Go 1.25:** a new collector, "Green Tea", was available behind `GOEXPERIMENT=greenteagc` at build
   time; the notes expect a 10 to 40% reduction in collection overhead for programs that use the collector
   heavily, with results varying.
2. **Go 1.26:** it is on by default, with `GOEXPERIMENT=nogreenteagc` as the build-time opt-out that the
   notes expect to be removed in Go 1.27. Measure on the toolchain you ship, and re-measure after upgrading
   (own guidance): a number taken on an older toolchain is not evidence about a newer one.

## 3.3 Detecting leaks versus cost
Heap profiles show current and past allocation and are the documented way to look for memory leaks;
`runtime.NumGoroutine` is listed as a way to detect goroutine leaks. Go 1.26 adds an **experimental**
goroutine-leak profile (`GOEXPERIMENT=goroutineleakprofile` at build time, served at the
`/debug/pprof/goroutineleak` endpoint), which reports goroutines blocked on a primitive that can never be
unblocked. Experimental in 1.26: do not make it a gate.

## 3.4 Transparent huge pages
The guide notes that on Linux, transparent huge pages can improve throughput and latency of programs with
big heaps (1 GiB or more) at a small memory cost, while programs with small heaps may use substantially more
memory. Leave this to the platform owner and test it per workload.

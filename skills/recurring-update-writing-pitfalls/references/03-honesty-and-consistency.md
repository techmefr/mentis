# recurring-update-writing-pitfalls §3 — Honesty and consistency

## 3.1 Never invent
1. **Never invent the company's metrics, customers, quotes, testimonials or team.** The emotix conventions
   say to leave a bracketed placeholder naming what goes there when the data is missing.
2. **A missing metric is stated as missing or omitted**; a fabricated one destroys the value of the whole
   update (Pitchdrive). The ir-kit prompt says to use only the supplied data files.
3. **Query a figure that looks wildly different from last time** once before using it (Pitchdrive's example:
   off by a factor of ten).
4. **Never present a guess as a fact** (emotix). An estimate is marked "Estimate:" with its arithmetic, and a
   claim with no source is "Not found".
5. **Outside facts need a source and a date**: prices, benchmarks, market figures (emotix).
6. **List assumptions at the top** of the output, each marked as an assumption, when only some inputs exist
   (emotix).

## 3.2 Match the voice, not the hype
1. **Write in the owner's voice**: read a few paragraphs of their earlier updates and match them
   (Pitchdrive).
2. **Do not editorialise highlights into hype**; lowlights must be real, not token (ir-kit).
3. **Match style with the series.** Keep the same metrics in the same order from one update to the next
   (ir-kit); own guidance: change the set deliberately and say so.

## 3.3 Consistency before an outside review
ir-kit's data-room audit prompt is written for a startup's fundraising documents. Read it as one example of
checking before someone else does; it is not a legal checklist, and what a given document must contain has to
be checked against official texts and a qualified person.
1. **Compare every document against its source**: a cap table export against the cap table data, a metrics
   one-pager against the financial data. The prompt calls inconsistent numbers across documents the most
   common red flag in diligence.
2. **Check dates**: mark a document as stale when it is undated or old (the prompt uses six months for
   financials, an example).
3. **List what blocks first**: the prompt names contractor and employee IP assignments, signed investment
   instruments with their side letters, a current cap table export and recent bank statements as items that
   stall a closing. Treat that as that author's list, not yours.
4. **Do not create placeholder documents.** Real gaps stay visibly open, each with who, what and by when.

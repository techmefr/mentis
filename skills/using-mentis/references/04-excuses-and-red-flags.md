# using-mentis §4 — Excuses and red flags

> Section 4 of `skills/using-mentis`. Read it when you notice yourself reasoning about why a block does not apply
> to this task, or why a question can come before choosing one. **These excuses are predicted, not recorded**:
> written before a run exists. When `skills/testing-blocks` §1 yields the sentences a run without this block
> really produced, replace them here, verbatim, and drop this notice.

1. **The excuses**

   | The thought | What is actually true |
   |---|---|
   | "This is just a question" | A question is a task. Choose the block, then answer. |
   | "I need more context first" | The block says how to gather it. Choosing comes before exploring. |
   | "Let me look at the repository quickly" | Looking is an action. Name the block first. |
   | "I remember how this block goes" | The text may have changed since you last read it. Read the current one. |
   | "It is overkill for this" | Small tasks get a short pass through the block, not a skipped one. |
   | "I will do this one thing first" | The one thing is usually what the block would have ordered differently. |
   | "It feels productive to start" | Motion without the method is how a step gets done twice. |
   | "No block quite fits" | Then it is out of scope or a gap to record (`skills/writing-skills`); not licence to improvise silently. |
   | "The change is a single line" | The direction of the pipeline holds even when most steps are one line long. |

2. **Red flags that mean stop and name the block:**
   - you have started editing and cannot say which block you are following;
   - you are about to say something works and have not run the command that shows it (`skills/gate` §8);
   - a checklist exists and no item of it is tracked;
   - you reviewed before the gate, or gated work you are still writing;
   - you are repeating a failed approach for the third time (`skills/debug` §4).

3. **Process before implementation.** When two blocks apply, the one that decides how to proceed runs first and
   the one that carries out the work second: a bug report enters at `bug-triage` before the stack's conventions;
   a new feature enters at `brainstorm` before any implementation block. The process block sets the approach; the
   implementation block follows it.

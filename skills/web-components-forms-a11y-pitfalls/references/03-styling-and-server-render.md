# web-components-forms-a11y-pitfalls §3 — Styling across the boundary and server rendering

Source: the WHATWG HTML standard (parsing and scripting chapters), read 2026-10-20 (CC BY 4.0), plus own craft knowledge, marked where it is the latter. Styling-hook behaviour (parts, cascade of encapsulation contexts, slotted selectors) was re-read in the W3C CSS Shadow Module drafts and CSS Cascade Level 5 (W3C document licence, facts only); adopted style sheets were read in the W3C CSS Object Model editor's draft on 2026-10-20.

## 3.1 Styling hooks
1. **Symptom: the page's stylesheet does not restyle the element's inside.** Cause: selectors do not cross the shadow boundary, by design. Fix: offer three hooks and nothing else. Custom properties (they inherit across the boundary) for colours, spacing and fonts; named parts for the few inner nodes a page should restyle (an element gets a part name through its `part` attribute and is matched from outside with `::part()`); slots for content the page owns.
2. **Symptom: the element ignores the page font or colour.** Inheritable properties flow in, non-inherited ones do not; and a reset in the root can cut inheritance. Check what the element sets on `:host` and what it leaves to inherit.
3. **Symptom: page styles win over the element's default styles on the host.** Styles on the host from the page beat `:host` rules inside the root. This follows the cascade rule for encapsulation contexts: for normal declarations the outer context wins, for important ones the inner context wins, so `!important` inside the root is how an element enforces a requirement. It is useful for overriding display or margin, and a trap when the element needs `display: block` to lay out. Document which host properties the page may override.
4. **Do not expose every inner node as a part.** Each part is a promise; renaming it later breaks users. Name parts after what they are for, not after how they are built.
5. **Forward parts deliberately.** A part of a nested element is not reachable through a chained `::part()::part()`; the standard blocks it so internal structure stays private. To let the page reach it, the outer element re-exports it with the `exportparts` attribute, which is one more promise to keep (§3.1.4).
6. **Do not open or reach into a root to restyle it** from outside, and do not close it to prevent that (§2.4.3). The hooks above are the contract.
7. **Share one stylesheet object across instances** where the platform allows it, instead of one `<style>` per instance. The CSS Object Model defines a constructed style sheet and an adoptedStyleSheets list on every document and shadow root, and the root's final list is its own sheets first, then the adopted ones in array order (so an adopted sheet beats a `<style>` of equal specificity). Three traps from the standard: a constructed sheet can be adopted only by roots in the document it was constructed in (otherwise NotAllowedError, as with a sheet built in an iframe), `replaceSync` silently drops any `@import` rule, and `insertRule` of an `@import` into a constructed sheet throws a SyntaxError. Check the engines you target for support.

## 3.2 Slots and light-DOM content
1. **Symptom: styling the slotted content from inside the root has little reach.** Slotted nodes belong to the page's tree, so the page styles them; the root can style the slot element and, through the slotted-selector pseudo-element, only the elements assigned directly to the slot, not their descendants. Fix: leave typography of slotted content to the page, and expose spacing through custom properties.
2. **Symptom: a label slotted into the element does not name the inner control.** See §2.1.5.

## 3.3 Declarative shadow DOM and server rendering
1. **Symptom: server-rendered custom elements flash unstyled content, then pop into shape.** Cause: the element's markup and styles live in the class, which has not loaded yet. Fix: serialise the shadow root into the HTML as a template element carrying a shadow-root mode attribute (the standard names it `shadowrootmode`), so the browser attaches the root while parsing and the first paint already has the structure and styles.
2. **The same template element takes attributes for delegated focus, serialisable and clonable roots**, set on the template, matching the options of `attachShadow`. Symptom of omitting delegated focus on the server markup: two tab stops until the class upgrades (§2.2.1).
3. **When the class upgrades, it must reuse the existing root.** Symptom: the content duplicates, or the root throws on a second attach. Fix: in the constructor, use the internals' view of an existing shadow root before attaching a new one, and render into it only if it is empty or stale. The internals expose a `shadowRoot` getter; it returns the root of a declarative shadow root and the root a custom element attached to itself with `attachShadow` (closed or open), and null when the host has no shadow root or the root was attached to a host that is not a custom element.
4. **Declarative roots are parsed only through the parser paths that support them.** Setting `innerHTML` does not create them; use the unsafe parsing entry points (`setHTMLUnsafe`, `parseHTMLUnsafe`; the legacy `innerHTML` mode disables declarative roots), with the usual sanitising rules (`skills/csp-and-sanitiser-pitfalls`). Symptom: a template element that stays inert in the DOM.
5. **Server and client must produce the same markup.** Symptom: hydration warnings, or the client replaces the whole subtree and loses focus and typed text. Fix: render from the same inputs, with no timestamps, random ids or browser-only reads on the server path (`skills/nuxt-no-hydration-nondeterminism` for the same rule in Vue).
6. **A form-associated element renders its value for submission only after upgrade.** Until the class loads, the element submits nothing (§1.1). Symptom: a submit before scripts finish drops the field. Fix: keep a native fallback inside the server markup (a real input that the class takes over), or disable submission until upgrade.
7. **Do not throw in the constructor when the document is not a browser** (§1 of `web-components-lifecycle-pitfalls`); the constructor may run on a server shim with no layout.

## 3.4 Checks
1. Load the page with scripts blocked: readable, styled, no layout jump when they load.
2. Throttle the script, submit the form early, and see what is sent.
3. Inspect the upgraded element: one shadow root, one copy of the content.
4. Restyle one inner part and one custom property from the page; remove a part from the element and see what breaks (it should be a documented change).

# agent-data-gap-honesty-pitfalls §2 — Chain seams

> Part 2 of `skills/agent-data-gap-honesty-pitfalls`. Read it when a number passes from one step or skill to
> another, or when a schedule or a time is promised. Source: the "chain seams" rules of a small-business plugin
> set (Apache-2.0), rewritten in our own words; points marked own guidance are ours.

A chain is not its steps; it is the joins between them. Each step can be right and the chain wrong, because a
value that is true in one step's world is read as true in the next.

## 2.1 One number, two universes
1. **A total may travel as context; it must not become the denominator of a ratio computed over a narrower
   universe.** Example of the failure: the whole company's revenue handed to a step that measures only the
   online store, so ad spend is divided by money the ads could not have produced and the return looks absurdly
   large. Check: before reporting a rate, say what the top and the bottom each measure.
2. **Compute every rate against the base the thing could reach.** Return on spend against the channel's own
   revenue, conversion against the visitors of that page, share of product against that catalogue. Name both
   figures in the sentence so the reader sees the base.
3. **A ratio far better than the field allows is a tell.** Look at the denominator before celebrating. Do not
   quote an industry figure from memory to judge it; compare with the person's own earlier numbers. Own guidance.
4. **At every hand-off ask what the value measured and whether the receiver measures the same thing.** If not,
   the value crosses as labelled context and never as an input to arithmetic.

## 2.2 A cadence nobody set
1. **Saying "saved, this runs every Monday" is a promise.** If no scheduler exists in the runtime, saving the
   word "weekly" stores a string and wakes nothing. Symptom: the person stops producing the report by hand,
   nothing arrives, and they conclude the tool is broken.
2. **Only say a schedule is set when something was scheduled**, and state what it will do, when and where the
   output lands.
3. **Where there is no scheduler, say so and offer an honest substitute**: a recurring reminder on the person's
   own calendar that says what to ask for. The definition can still be saved so the rerun costs one message.
4. **A cadence the person has to trigger is a real product; a cadence that was never set and was said to be is a
   broken promise.**

## 2.3 Times that are wrong by hours
1. **Establish the person's zone once and keep it.** Ask if unknown. Never take it from the calendar's default
   zone; that is where the account was created.
2. **Trust the offset inside a timestamp over the label next to it.** A zone label that contradicts the offset is
   an artefact. Wall-clock digits without the offset are not enough to convert.
3. **Convert into the person's zone and print the zone** on anything outward-facing or any meeting with
   attendees: "9:00 PT", not "9:00".
4. **When the signals disagree, say so.** One sentence ("these are stored as Eastern but labelled Pacific; I
   read them as Pacific, worth a look") costs ten seconds; a silent guess costs a missed meeting.
5. **An outward action (an invitation, a booking) with a wrong hour cannot be undone by an apology.** Be stricter
   there than for a summary.

## 2.4 A suggestion tool that says the day is free
1. **Never propose or book a slot on a suggestion tool's answer alone.** Such tools can report a day as available
   that has a conflict. Read the actual events for the candidate day and confirm the window is clear.
2. **Resolve the hour by offset first, then verify the slot is free.** The two checks stack; neither replaces
   the other.

# customer-interview-synthesis-pitfalls §2 — Quote versus inference

The most common silent error in interview write-ups is a sentence that reads like a customer's words and is the
interviewer's reading. Once it is in a slide, nobody can tell which is which.

## 2.1 Three layers, three lines
1. **Observation**: what the person said or did, as close to verbatim as the notes allow, with the question that
   prompted it. Symptom: notes that start with "they feel that...". Fix: write what was said first.
2. **Context**: who (participant code, role, segment), when, which occasion they were describing.
3. **Inference**: your reading, marked as yours. Quotation marks are for the first layer only.
4. **Keep the layers in separate columns or lines** so a later reader can drop an inference without losing the
   fact.

## 2.2 One fact per line
1. **Split compound notes.** "Hates the export, uses spreadsheets, wants dashboards" is three observations with
   three different strengths. Symptom: a theme count inflated by one sentence that carries several tags.
2. **Record what was unprompted.** A pain raised before you asked about it weighs differently from one agreed to
   when you named it. Mark which is which.
3. **Record behaviour next to opinion.** If someone says a task is easy and the recording shows a long
   workaround, keep both lines.

## 2.3 Coding that can be redone
1. **Write the tag list from the decision, then add tags as the notes demand**, and write down what each tag
   means. Symptom: two people tag the same line differently. Check: have a second person code a sample and compare.
2. **Code from the notes, not from memory of the call.** Memory keeps the vivid moment and drops the rest.
3. **Keep a participant code on every line.** A line without a code cannot be counted, checked or removed.
4. **Do not tidy a quote into better English** without marking the edit; keep the original beside the cleaned
   version if the cleaned one will be used in a deck or copy.

## 2.4 Traceability and handling
1. **Every finding links to the lines behind it**, and each line to a recording position or a note. A finding
   that cannot be traced is an anecdote.
2. **Notes and recordings are personal data.** Keep names and contact details in a separate sheet with a code
   key, limit who sees the recordings, and delete on the schedule you told participants (`business/data-protection`).
3. **Do not paste a customer's quote with name into a public place** without their consent for that use.

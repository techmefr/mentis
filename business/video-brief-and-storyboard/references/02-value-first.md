# video-brief-and-storyboard §2 — Value first

> Part 2 of `business/video-brief-and-storyboard`. Read it when an outline or script is drafted or reviewed.
> Source, read 2026-10-20 in the clone: the story-spine reference of an Apache-2.0 HTML-to-video framework
> (read in full, about 4 KB), and the story steps of its product workflow. Examples are ours. Sentences marked
> "own guidance" are ours. Not marketing advice (`business/README.md`).

## 2.1 The hook speaks the viewer's language
1. **The first beat answers "why should I care" in what the viewer gains, avoids or finally understands.** The
   source calls this outcome language and bans the subject's own vocabulary from the hook: file and function
   names for a code change, a feature list for a product, the section headings of an article for an explainer.
2. **A number belongs in the hook only when it carries stakes.** The source's distinction: a number that says
   what changes for the viewer is welcome, a number that is only an inventory is not. Own examples: "pages
   open before you finish reaching for the mouse" says what changes; "forty-one components changed" is an
   inventory of the work.
3. **The voice stays what the piece needs.** The source adds that leading with value is a decision about
   order, not a licence for hype: a video explaining a code change can keep a plain, matter-of-fact developer
   voice and still open on what the change does for the person watching.

## 2.2 Value before evidence
1. **Land the claim by the second beat.** The message from the brief (§1.2) is stated early; everything after
   it is evidence in service of it: the demonstration, the mechanism, the screenshots, the diff. The source's
   phrase is a reverse iceberg: the viewer sees why it matters first and the implementation underneath it.
2. **Implementation is a footnote of the story.** Own guidance: if the how is what the audience actually
   needs (a tutorial), that is a different message and a different brief; decide it in §1.2, not in the edit.
3. **A piece whose story is already fixed does not need this.** The source exempts videos where the music, the
   footage or the presenter fixes the order. Do not force the rule on those; use it where the video has to
   persuade or explain from nothing.

## 2.3 The delete test, both ways
Run it on the finished list of beats.
1. **Delete every evidence beat.** What remains must still state the value on its own. If it does not, the
   claim was never made; the evidence was carrying it.
2. **Delete the value beats.** If the video still seems to work, it was a tour of features or a readout of a
   change, not a story. Add the value, or say it is a tour on purpose and write it in the brief.
3. **Write the result of both tests in the outline.** Own guidance: two lines, "survives without evidence: yes
   or no; survives without value: yes or no". A reviewer can then argue with a result instead of a feeling.

## 2.4 Not covered
Whether the claim is true and can be backed up is `business/marketing-claim-substantiation-pitfalls`; the
voice and the wording are `business/content-creation`. Neither is answered by this ordering rule.
